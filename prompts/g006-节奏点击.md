# 节奏点击

- **分类**：游戏与交互
- **标签**：`canvas` `音游` `节奏`
- **难度**：★★★☆
- **成片时长**：可玩

> 光点落到判定线时点击，带连击与判定反馈，无需音频文件

## Prompt

```
用 Canvas 2D 做一个节奏点击小游戏，画布 900×1200（竖版），背景 #0B0E14。

轨道：4 条竖轨，等宽排列，每条轨道底部有一个判定区（高 120px，用极淡的白色渐变标示）。

音符：从画面顶部生成，向下匀速移动（800px/秒）。每个音符是一个 80×24 的圆角条，颜色按轨道区分——#4D96FF / #4FD1C5 / #FFD93D / #FF6B6B。

节奏：不接入音频文件，用固定的 BPM 120 在代码里生成音符时间表，每 0.25 拍（0.125 秒）在随机轨道生成一个，共 120 个音符后结束。

判定：按下 D / F / J / K（或点击四条轨道）时，检测对应轨道上距判定线最近且在 120px 内的音符：
- 偏差 < 25px → 「PERFECT」，+100 分，金色文字。
- 25-60px → 「GOOD」，+50 分，青色文字。
- 60-120px → 「MISS」，连击清零，灰色文字。
- 音符越过判定线未击打 → MISS。

反馈：
- 命中时判定区闪光一次，并从命中点炸开 10 个粒子。
- 连击数在画面中央上方显示（字号 48px），每 10 连击放大一次并变一次颜色。
- 命中的音符条向上飞散消失（0.2 秒内透明度归零、缩小到 0）。

结算：全部音符结束后显示总分、最大连击、PERFECT/GOOD/MISS 各自数量，按 R 重开。

要求：单文件 HTML，所有时间用 performance.now() 计算而非帧计数（避免掉帧导致节奏漂移），不加载任何音频文件。
```

## 调参提示

音游的命脉是「用时间而非帧数驱动」。掉一帧不影响节奏，但如果用帧计数累加，一次卡顿就会让后续所有音符全部偏移。
